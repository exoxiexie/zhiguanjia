# 后台管理系统 · 路线图

## 已完成

| 模块 | 内容 |
|---|---|
| 运营看板 | 装机/活跃/新增、实名、版本与平台分布、内容量、使用深度、近 14 天趋势 |
| 博客发布管理 | 文章列表/新建/编辑/草稿/发布/删除；链接按标题自动生成；发布=构建+上线 |
| 系统管理 · 站点 | 站点目录与内容量状态、**发布站点**、最近一次发布记录 |
| 公告与配置 | 公告（含"重新弹一次"）、强制更新（含当前版本参考与一键关闭）、功能开关（含测试入口灰度名单）；记录最后修改人 |
| 系统管理 · 数据 | **备份与恢复**：备份数据库/文章内容/上传文件/配置；恢复前自动保存现场；保留最近 N 份；每日 03:30 自动备份 |
| 系统管理 · 安全 | **操作审计**：中间件自动记录所有 /admin 写操作（含失败与越权尝试），带操作者/对象/结果/IP |
| 版本发布 | 上传 APK（草稿→发布）→ 写更新源 → 铺官网下载页 → 重建发布 → 可选强制更新 → 历史归档；版本号必须递增 |

## 规划中（按优先级）


### 第二批（内容与用户）
4. **版本发布**：上传 APK、填更新说明、同步更新源与官网下载页、灰度与回滚
2. **用户管理**：用户检索、实名状态、设备与登录情况、封禁/解封
3. **内容审核**：说说与对话内容巡检、举报处理、违规下架
4. **反馈处理**：用户反馈与工单的收集、分派、跟进

### 发版自动化（未来）
- 当前：APK 仍需在本地编译（服务器无 Android 构建环境）
- 可选路径：接 Gitee Go / GitHub Actions 做 CI 构建，构建产物自动上传到后台，
  实现"推送 tag → 自动出包 → 后台点发布"的全自动链路

### 加固（健壮性）
- **危险操作二次确认**（发布站点、删除文章、注销账号）
- **权限分级**：只读 / 运营 / 超管，按模块分配
- **后台独立子域名 + IP 白名单**（备案完成后可做，等价于给后台加一把锁）
- **后台独立版本号与发版说明**（当前跟随服务端版本）
- **监控与告警**：后台接口错误率、发布失败通知

### 架构演进（有明确触发条件再做）
- 当前：同一 FastAPI 进程 + 同一数据库（刻意共用账号体系，避免重复实现认证与模型）
- **触发条件**：需要独立扩缩容 / 独立发版 / 更强隔离时，按 `server/app/admin/` 边界
  抽成独立服务与子域名（目录边界已经立好，抽离成本约半天）
