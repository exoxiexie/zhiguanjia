## 环境坑：flutter test 与 APK 构建都需绕开代理（重要）

- 会话沙箱注入了透明代理（`HTTP_PROXY=http://127.0.0.1:52838`，仅存在于 Agent 命令执行环境，**不是用户终端 / 项目本身的问题**）。它拦截本地回环连接，导致：
  - `flutter test` 报 `Unable to connect to flutter_tester process: WebSocketException: Invalid WebSocket upgrade request`；
  - `./build_apk.sh` 的 Gradle 依赖解析挂死（实测干跑 10 分钟零产出）。
- 统一解法：所有 flutter/gradle 命令都前缀
  `env -u HTTP_PROXY -u HTTPS_PROXY -u http_proxy -u https_proxy NO_PROXY="127.0.0.1,localhost" no_proxy="127.0.0.1,localhost"`。
- 判断构建是否真卡死：看 `build/app/outputs/flutter-apk/*.apk` 时间戳是否更新、`find build -newermt "-60 seconds"` 是否有写入。
- **不要在 Agent 沙箱里跑 APK 构建**：Dart AOT（`gen_snapshot`，-Xmx4G 的 Gradle daemon）会把沙箱 CPU 全部占满，连带把用户整机/输入框拖到卡死。约定：代码改完由**用户在自己终端**跑 `./build_apk.sh`（本机无代理，3–4 分钟出包）；Agent 侧只负责改代码、升版本号、写 CHANGELOG，不主动起重型构建。
  - 补充实测：用**关闭沙箱**（`dangerouslyDisableSandbox`）的方式构建可成功出包，但仍会占满 CPU；本次因前两次构建被中断导致增量缓存失效，全量重编耗时 **11 分 25 秒**（正常 3–4 分钟）。
