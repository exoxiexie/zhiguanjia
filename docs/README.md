# docs/ · 文档地图

> 项目文档较多，这里说明**每份文档管什么、谁是权威**，避免"两套事实来源"。

| 文档 | 权威范围 | 维护时机 |
|---|---|---|
| **`项目台账.md`**（仓库根） | **项目级唯一权威**：现状、关键决策、待办、运维规范、测试基线 | 每次交付/决策后 |
| `docs/开发记忆/MEMORY.md` | **App 工程细节参考**：App 内部结构、组件约定、实测尺寸/性能数据、发版操作步骤 | 相关改动后 |
| `docs/开发记忆/YYYY-MM-DD.md` | **历史工作日志**（只增不改），记录当日改动与发版结果 | 归档，不回填 |
| `CHANGELOG.md` | 每个版本的**变更内容**（面向版本） | 每次发版 |
| `KNOWN_ISSUES.md` | **缺陷与风险台账**（含根因、修法、验证） | 每次修 bug |
| `商业版改造方案.md` | P0–P6 **阶段方案与架构说明** | 阶段变更 |
| `admin/README.md` · `admin/ROADMAP.md` | **后台产品**的约定与模块版图 | 后台改动 |
| `README.md` | 面向新人的项目入口说明 | 偶尔 |

## 关于 `docs/开发记忆/` 的来历

原目录名为 `.workbuddy/memory/`，是**上一套 AI 助手（WorkBuddy）**在开发本项目时写的记忆目录。
内容全部是**本项目的**（发版规范、工程事实、每日工作日志），与产品本身无依赖关系；
为免"两套事实来源"，已迁到 `docs/开发记忆/` 并在此说明其定位：

- **仍然有效**：发版报告规范、版本号约定、App 工程事实、构建性能参数、发版操作步骤
- **以台账为准**：项目现状、关键决策、待办清单、运维规范（若与本目录冲突，**以台账为准**）
- **仅作史料**：每日工作日志（记录当时的改动与发版结果）
