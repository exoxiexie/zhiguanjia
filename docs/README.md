# docs/ · 文档地图与**阅读规则**

> 本文件的第一作用是**规定读什么、不读什么** —— 防止过期的历史信息污染当前上下文。

## 一、三级分类（开工必守）

| 级别 | 含义 | 是否进上下文 | 文件 |
|---|---|---|---|
| **L0 权威** | 项目级唯一事实来源，**必须最新** | ✅ **开工先读** | `项目台账.md` |
| **L1 现行** | 按需阅读的现行文档，**只保留能被当前状态验证的内容** | ✅ 按需读 | `CHANGELOG.md`（近期）· `KNOWN_ISSUES.md` · `商业版改造方案.md` · `admin/README.md` · `admin/ROADMAP.md` · `docs/app-工程参考.md` · `README.md` |
| **L2 归档** | 当时有价值、**今天已过期**的过程性记录 | ❌ **默认不读** | `docs/archive/**` |

## 二、规则

1. **开工只读 L0**，需要时再读相关 L1；**永远不主动读 L2**
2. **引用任何信息前先核对时效**：看待办/风险/结论，先确认它**现在是否仍成立**
   （真实教训：2026-10-06 的一条"凭据暴露"待办，2026-10-10 被误当作当前风险上报）
3. **一件事解决后**：结论写进 L0 或 `KNOWN_ISSUES.md`，**过程性记录移入 L2 并登记索引**
4. **L1 条目过期**：要么更新，要么移入 L2 —— 不允许"过期内容留在 L1"
5. **L2 例外**：仅当用户**明确要求追溯历史**时扫描；扫描出的结论**必须按当前代码/线上状态复核**后才能用于决策
6. **新建文档**：先判断它属于哪一级，在 L0 的「文档索引」登记
